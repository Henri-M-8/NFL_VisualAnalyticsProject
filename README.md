## Project question and deliverables

This report studies how in-game state relates to home-team win probability, which plays create the largest probability swings, and how fourth-down conversion outcomes vary with distance and field position. It follows the proposal's hallmark dynamic game-flow view and secondary fourth-down decision-analysis suite. It contains **seven visualizations** that help both coaching staff and media outline this data to others and make more educated decisions.

## Case study 1 — Following a high-volatility game

**User and need.** A broadcast analyst wants to explain how a game moved from one side's control to the other's, distinguish large swings from routine plays, and communicate whether a probability trace is consistent with the final result. The guiding questions are: *When did the game change, what happened on those plays, and how did the win forecast respond?*

**Analysis path.** The notebook selects the held-out game with the largest cumulative absolute play-to-play change in the source win-probability estimate (or uses `CASE_GAME_ID` if set). Following Yurko et al.'s continuous win-probability and leverage-point analysis, the reader moves from the full-game trace to annotated high-swing plays and then drive-level changes. The interactive timeline, event filters, and linked field/detail views apply the focus-plus-context and coordinated temporal/spatial exploration described by Perin et al. in *SoccerStories*. This sequence lets an analyst move from an overview to a specific event and inspect its game and field context.

**Observed result in the default saved run.** The selected game is Baltimore at Cleveland on October 7, 2018; the score was tied **9–9** at the end of regulation, and Cleveland won **12–9 in overtime**. Cleveland's late fourth-quarter completions moved the Browns into position for Greg Joseph's 55-yard field-goal attempt, which missed with nine seconds left; the game therefore continued tied. The raw `home_wp_post` value drops from about **0.922 to 0.025** around that miss despite the unchanged tie score, and similar abrupt values occur on overtime timeout rows. That conflict with the scoreboard is a data/model consistency warning, not evidence of a real 90-point change in Cleveland's chance. The trace should be cross-checked against score, clock, and the independently trained model; the event and drive views help locate the discrepancy. The selection rule and plots update if another game is selected, but this prose describes the default saved run.

**Value and limits.** These views offer an auditable narrative for broadcast review and post-game discussion. The learned model is a retrospective benchmark, not a live betting forecast or causal estimate. The source probability is a separate reference model, not ground truth. Large swings are descriptive and do not prove that an individual decision caused the outcome.

## Case study 2 — Evaluating fourth-down choices

**User and need.** An offensive coordinator or analyst wants to review whether fourth-down attempts have different observed conversion rates by yards-to-go and field position, and where a go-for-it discussion merits closer review. Questions include: *How does distance relate to conversion? Where on the field are attempts concentrated? Are apparent differences based on many attempts or small samples?*

**Analysis path.** The notebook isolates fourth-down plays with explicit converted/failed outcomes, summarizes conversion rates and sample counts by distance, and maps observed rates onto a custom 100-yard field display. This connects to Yurko et al.'s discussion of field position and fourth-down decision analytics. EPA by down and play type provides broader play context; the spatial map and linked views also follow the SoccerStories principle of reading event patterns alongside field context. These are descriptive views: teams select when to attempt a conversion, so rates alone cannot establish whether attempting is better than punting or kicking.

**Observed result on the supplied archive.** There were **4,776** recorded fourth-down attempts with explicit outcomes, with an overall conversion rate of **49.0%**. One-yard attempts converted **64.7%** of the time (1,787 attempts), compared with **20.5%** for 11-or-more yards (493 attempts). The plot adds Wilson intervals and counts; the difference is descriptive and reflects which situations teams chose to attempt.

**Value and limits.** The displays help analysts find patterns and follow up on decisions, but do not estimate counterfactual kick/punt value, adjust for every tactical factor, or prescribe a coaching action. The field map shows historical outcomes, not a forecast. Cells with fewer than ten attempts are marked as sparse.

## Visualization & reproducibility

Figures 1–5 are the five core individual-project visualizations; figures 6–7 are custom-coded designs submitted for bonus consideration. They directly map data to encodings (the yard-line field cells and variable-width drive-impact arrows), rather than relying only on standard chart calls. Bonus eligibility and novelty remain for the instructor to assess. The interactive hub is the coordinated interface for these views, not an additional visualization counted toward the five. The model trains on seasons 2009–2016 and tests on 2017–2018; its **log loss** and the source `home_wp_post` reference log loss are reported on the same held-out snapshots. The source probability is not a predictor feature. Tied games are excluded from this binary home-win/loss target rather than mislabeled as losses. A deterministic, within-game snapshot sample limits repeated-play dominance. Prediction scores describe probability quality, not causal effects.

Candidate model settings are compared on the 2015–2016 validation seasons (original features: **0.4842**; engineered features: **0.4834** log loss). The selected model is then retrained through 2016 and evaluated on the separate 2017–2018 test seasons. On that held-out test, the original-feature baseline scored **0.4348**, the selected engineered-feature model scored **0.4339**, and the source `home_wp_post` reference scored **0.4359**. Lower is better; the improvement is small and does not establish better performance on future seasons. The source probability is shown as a reference, not training ground truth.

## Documentation & reporting: create the environment and run

1. Install Python 3.10 or later. From the project folder, create a virtual environment with `py -m venv .venv`.
2. Activate it in PowerShell with `.venv\Scripts\Activate.ps1`. On macOS or Linux, use `source .venv/bin/activate`.
3. Install the dependencies listed for this project: `python -m pip install --upgrade pip`, then `python -m pip install -r requirements.txt`.
4. Open `HenriMurthyVisProject.ipynb` in VS Code. Select the `.venv` Python interpreter as the notebook kernel, then run all cells from top to bottom. The `.venv` folder is created locally and does not need to be included in the repository.
5. The notebook uses KaggleHub by default to download the public dataset `maxhorowitz/nflplaybyplay2009to2016`; it checks that the data covers seasons 2009–2018 before modeling. If KaggleHub cannot download it, place the dataset CSV in the project folder with a filename containing both `2009` and `2018`. The CSV can be downloaded from [the Kaggle dataset page](https://www.kaggle.com/datasets/maxhorowitz/nflplaybyplay2009to2016). Kaggle credentials may be required by your local Kaggle setup; never put a token in the notebook. The large ZIP archive used during development is not included in the repository.
6. Run the final Interactive Visualization Hub cell to open the main menu. Select a view and, for game-specific charts, a game; hover for details and use Plotly's toolbar to zoom or pan. If widgets fail to display, confirm the notebook is using `.venv` as its kernel and that the dependencies installed successfully, then restart the kernel and run the cells again.
7. Review the printed data source, season coverage, sample counts, and model evaluation before interpreting the figures.

## Interactive hub — coordinated game flow and linked detail

This interactive overview is modeled on the proposed interface mockup in the project survey: selected-team win probability with momentum on a secondary scale, quarter shading behind the chart lines, a separate elapsed-time event timeline, key-event filters, field-position context, and fourth-down coaching choices. Its compact legend sits outside the plotting canvas. The field-position maps use a yard-line and end-zone overlay, while game-specific charts use color-coded home/away abbreviation badges. These are compact team identifiers, not official logos; actual logo artwork can be embedded if licensed image files are supplied. Choosing a linked play highlights both its time on the game-flow chart and its field location. Use the visualization menu to explore each of the seven detailed charts. Plotly figures resize to the available notebook width, and the controls and legend wrap on narrower layouts.
